# ADR-0001 · 产品范围与技术选型

日期：2026-09-28 ｜ 状态：已接受（grilling 共识定稿）

## 背景

为"临池读帖"场景建一个碑帖原文+释义的阅读工具。经过逐项决策访谈（grilling），以下选择已定。

## 决策

1. **形态：纯静态网站**。无账号、无编辑器、无笔记功能；不是 CMS，不是 App。
2. **技术栈：Astro + Vue 3 island**。仅"阅读器"为 Vue island，其余页面静态渲染。
3. **内容即代码**：内容以结构化数据（句对）存于仓库，随 git 版本化；新增碑帖 = 加数据，不改代码。
4. **部署：Netlify**（连仓库自动构建）。
5. **定位**：自用为主，但内容按可公开版权标准生产（自标点、自注译，不搬在版权注本）。
6. **收录策略**：碑帖跟着临习进程收录（写到哪本做哪本），另备经典 roadmap 清单（只列名目）。
7. **书论分支搁置**：数据结构留 `category` 扩展位，本版不做任何书论功能。

## 被否决的备选

- **Nuxt Content / VitePress / 与博客同栈**：均满足静态需求，Astro 在内容集合管理与 island 架构上最合（详见访谈记录）。
- **app 内编辑（Notion 式知识库）**：功能量大增，且丢掉 ZCode 核对文献的生产能力。
- **内容存数据库/Headless CMS**：自用场景下 git 纯文本最可持久、可回溯、可公开。
