# 「读帖」碑帖深读静态站 · 规格（Spec）

> 状态：待确认（见文末"待用户确认项"）｜依据：2026-09-28 需求 grilling 共识 + D 稿「句读」原型四轮迭代 + design-prompt.md 红线
> 发布：本仓库；实现启动时发布至 issue tracker，打 `ready-for-agent` 标签

## 问题陈述（Problem Statement）

我在临池学书时，需要对着碑帖读原文、明文意（如《集王圣教序》这类集字碑的骈文，不读释义根本读不下去），但现状是：纸质字帖只有原文没有释义；网上译文与碑刻用字对不上、繁简混杂、版本异文无人交代；而且没有任何工具是"为临池读帖设计"的——要么是图片库，要么是普通文章页。我需要一件顺手的工具：写字前中后打开，一句原文跟一句释义、像翻一本古籍集注那样逐页读。

## 方案（Solution）

一个纯静态网站「读帖」：收录名碑帖，每本碑帖是一个"电子集注本"——**书本式翻页阅读器**，基本单元是"句对"（一句繁体竖排原文 + 紧跟的一句简体小字释义），版式取法古籍（宣纸底、乌丝栏界格、文武版框、朱砂点缀），支持繁/简、竖/横、字号切换与自动重分页。内容跟着临习进程收录，按可公开的版权标准自产（自标点、自注译）。技术栈 Astro + Vue island，部署 Netlify。首篇《集王圣教序》内容已核对完毕。

## 用户故事（User Stories）

**作为临池读者（作者本人）：**

1. 作为临池读者，我想打开一本碑帖就进入逐页深读——一句原文、紧跟一句释义，视线不离开当前列，这样写字间隙读帖不被打断。
2. 作为临池读者，我想原文默认**繁体竖排、从右起**，与碑刻原貌一致。
3. 作为临池读者，我想一键切换原文为简体（只切原文、释义恒简体），读文意更快。
4. 作为临池读者，我想一键切换横排版式，疲劳时降低竖排阅读负担。
5. 作为临池读者，我想调节字号（A－/A＋），案头远看也清楚。
6. 作为临池读者，我想任何切换（繁简/竖横/字号）或窗口缩放后**自动重新分页**，永远不出现半句截断、文字溢出书页。
7. 作为临池读者，我想用多种方式翻页——点书页两角（悬停有提示）、方向键、滚轮、底部按钮——且符合竖排书习惯**向左翻**。
8. 作为临池读者，我想要汉字页码和页码直达链接（#pN），方便记下并回到上次读到的地方。
9. 作为临池读者，我想一键跳到某段（如"段三·玄奘西行"），复习名段不靠连翻。
10. 作为临池读者，我想先在**扉页**看到碑帖元信息（朝代/撰文/书者/书体/原石），像展签一样交代清楚。
11. 作为临池读者，我想在读完后看**跋页校记**，明白"涂间失地之涂通途""蹑霜雨一作霜雪"这类版本细节，知道译文为何这样读。
12. 作为临池读者，我想在列表页按朝代/书体浏览已收录碑帖，并看到"计划中"清单，知道接下来临哪本、配哪篇。
13. 作为临池读者，我想阅读区占满视口（宽 ≥ 2/3、高 ≥ 3/4），顶栏和页脚极薄——工具让位于书。
14. 作为临池读者，我想文字**严格落在界格内**、没有无字的空格子、界格线清晰但不抢眼——版面像真的古籍，不像半成品表格。
15. 作为临池读者，我想要纸墨气质的视觉（宣纸、墨、朱砂三色体系），没有 SaaS 感的圆角卡片与渐变，久看不腻。
16. 作为临池读者，我想全站离线可用（纯静态、系统字体栈），书案旁没有网也能读。
17. 作为临池读者，我想手机/平板上也能基础阅读（单列版式、触摸翻页）。

**作为内容维护者（作者，借助 ZCode 协作）：**

18. 作为内容维护者，我想新增一本碑帖只需添加一个内容条目（结构化句对数据），不需要改任何代码。
19. 作为内容维护者，我想内容入库时被自动校验：繁/简句数一致、拼接后与底本全文一致、段落完整、释义不缺——坏数据进不了库。
20. 作为内容维护者，我想所有内容按可公开版权标准生产（自标点、自注译，不摘录在版权注本），将来公开零负担。
21. 作为内容维护者，我想内容与代码同在 git 里版本化，每篇的修改可回溯。

**作为（未来的）访客：**

22. 作为访客，我想无需注册直接阅读全部内容，页面由 CDN 秒开。

## 实现决策（Implementation Decisions）

1. **架构**：Astro 纯静态站点；仅"阅读器"为 Vue 3 island，其余（列表、扉页、跋页信息）为静态渲染。无后端、无客户端持久化存储。
2. **内容层**：Astro content collection，一碑帖一条目；元数据（碑名/别名/朝代/撰者/书者/书体/原石/状态/校记/段落表）+ 结构化正文（句对数组）。**禁止**把句对散写成自由 markdown。
3. **句对数据形态**（源自 D 稿原型，编码了核心决策——释义为白话恒简体、繁简双存不做运行时转换以保留碑刻用字）：

   ```
   句对 unit = {
     d: 段号(1..n),
     f?: 段首标记(该段第一句, 渲染朱色段号),
     t: 繁体原文句（含标点，以。；？分句）,
     s: 简体原文句（与 t 逐句对应）,
     z: 简体白话释义句
   }
   ```
4. **分句规则**：以。；？为界切句；逗号不切。分句在内容生产时确定并随数据存储，不做运行时切分。
5. **阅读器 island**：输入 = 条目全量数据；内部状态 = 当前页、繁/简、竖/横、字号；支持 `#pN` 深链直达页；段跳转按钮按分页结果定位到段首页。
6. **分页引擎**：测量式贪心装箱——与书页同尺寸的隐藏探针容器逐句对追加，溢出即切页；繁简/竖横/字号/视口任一变化后防抖重分页。行为契约：分页结果无丢句、无重复、保持语序、单页不溢出。
7. **版式硬约束（红线，实现不得突破）**：
   - 文字必须在界格内：v2 采用**字级装箱**（每字一格固定入栏，列宽=界行宽），空余栏位以隐藏槽位补齐界格——古籍"界格通栏、字不满格留白"原貌（v2 修订，取代 D 稿"界格只画到文字高度"方案）；
   - 原文与释义之间一道细朱线（约 1.5px、朱砂 45% 透明度）分隔；
   - 书页占视口宽 ≥ 2/3、高 ≥ 3/4；chrome（顶栏+页码条）最薄化；
   - 原文楷体 ≥ 28px、释义宋体 ≥ 17px 默认值，可调；
   - 线装为默认形态，向右翻（右角=后一开）；卷轴为可选模式，同页切换；
   - 界面无大圆角/渐变/投影卡片。
8. **视觉终稿**：v2 设计稿已定稿入库（designs/v2/），即视觉与交互最终基准；与红线冲突时，红线优先。**注意：designs/v2/pairs-data.js 的文案是含生造句的设计占位，正式内容一律以 content/ 的核对版数据为准。**
9. **列表页**：数据驱动；`published` 条目正常展示，`planned` 条目灰置只显名目，不生成详情页。
10. **部署**：Netlify，连 git 仓库自动构建；无其他环境。
11. **扩展位**：collection 预留 `category` 字段（本版仅 `stele`；未来书论 `treatise` 挂同构条目），但本版不为书论做任何功能。
12. **阅读进度**：V1 不做持久化，仅页码 hash 直达。

## 测试决策（Testing Decisions）

- **好测试的标准**：只测纯核心模块的外部行为——给定输入（内容条目、容器度量）断言输出（校验结果、分页序列），不测 DOM 结构、CSS、实现细节。
- **两个被测模块（也是本项目仅有的两个测试接缝）**：
  1. **内容解析与校验（纯函数）**：断言包括——繁/简逐句数量一致；繁体句拼接还原底本全文（与条目声明的全文校验串比对）；段号连续且段首标记唯一；每句释义非空；校验失败时报出精确到段/句的定位信息。
  2. **分页引擎（纯函数，度量以注入的 mock 传入，不依赖真实 DOM）**：断言包括——输出单元序列与输入全等（无丢失、无重复、不乱序）；给定度量下每页不超容量；空输入与单超限句对等边界有定义行为（单句对允许成孤页）。
- **先例**：新项目无先例，此二模块即首批测试。
- **UI 层**：V1 仅做轻量冒烟（Playwright：翻页可达末页、切换后重分页不报错）；视觉红线由实现模式结构性保证，不做像素级测试。冒烟若 V1 排期紧张可顺延至 V1.5，不阻塞发布。

## 范围外（Out of Scope）

- 书论（历代书论原文/译注）内容与功能——仅留 category 扩展位
- 临池笔记/心得功能
- 账号体系、多用户、权限
- 全文检索
- 拓片图片与图文对照
- 无 JavaScript 降级方案
- 移动端深度打磨（仅基础响应式 + 触摸翻页）
- 3D 仿真翻页动画（仅淡入+轻位移）
- 阅读进度云端持久化
- SEO、访问统计等公开运营事项
- 内容生产自动化流水线（仍按 ZCode 会话人工协作产出）

## 补充说明（Further Notes）

1. **内容生产工作流**（已由圣教序一文验证）：公有领域底本核对异文 → 标点分段 → 简体转写 → 逐句释义（AI 起草、人工校订）→ 撰校记（异文/通假/碑字）→ 结构化句对入库 → 校验通过。
2. **版权红线**：原文自标点，释义自产，不摘录任何在版权注本；繁体保留碑刻用字（涂/苞/砂/群等）。
3. **首批内容**：《集王圣教序》已完成核对（含序四段全文、逐句释义、校记）；roadmap 初始建议：雁塔圣教序、九成宫醴泉铭、多宝塔碑、玄秘塔碑、兰亭序（神龙本）、祭侄文稿——按临习进程启用。
4. **仓库与发布**：本仓库即项目主仓库（Astro 实现就地进行）；spec 建议后续发布至 issue tracker 并打 `ready-for-agent`。
